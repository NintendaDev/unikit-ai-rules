## Important disagreements and how to resolve them

| Topic | Source disagreement or gap | Rule decision / next check |
|---|---|---|
| CLI raw dispatch | Guide describes raw MCP tool calls; server route dispatches directly to Unity handlers | Use wire payloads and real Unity commands; server-only MCP functions are not raw commands |
| Readiness shape | Skill examples show flat readiness; resource implementation nests compilation/advice | Read actual `data.compilation`, `data.advice`, staleness and retry advice |
| Compilation wait | Python wrapper polls after reload; Unity 6 C# refresh avoids waiting across a requested compile | CLI must independently confirm readiness after reconnecting |
| Tool visibility | Group guide simplifies to core-only; skill distinguishes HTTP and stdio | Inspect session state; never call server-only manage_tools via CLI raw |
| Batch limit and execution | Docs advertise parallel reads and 25/100 limits; CLI wrappers cap 40 and C# currently serializes | Use lowest limit, explicit fail-fast, inspect each result; make no guaranteed speedup claim |
| Batch failure defaults | Source examples disagree; C# defaults failFast to false | Always set desired behavior explicitly |
| Test polling | MCP supports wait_timeout in Python; CLI handler is an immediate status read | Implement caller polling; do not assume CLI --wait implements the MCP loop |
| UI Toolkit source/capture | Skill templates expose fewer actions; generated docs and handler cover live edits/render pending | Use current contract; separate persisted source from live tree mutations |
| ProBuilder pivot/conversion | Skill flags known failures, generated catalog still lists actions | Record as version-sensitive verification needs, not universally proven defects |
| Image transparency | Import flag resembles a generation capability | Inspect alpha; remove_background is unsupported in the reviewed tool |
| Action-specific properties | Generic schemas leave many nested keys as arbitrary dictionaries | Consult the corresponding installed handler or detailed official reference on demand |

## Updating this rule family

1. Identify the installed server/plugin/CLI revision before adapting a payload. Compare both the MCP Python signature and Unity wire handler; check the CLI wrapper when using one.
2. Recheck the disagreements table only when the affected operation matters. Do not launch destructive probes or provider jobs merely to refresh this documentation.
3. Extend the existing task reference; create another only for a genuinely separate loading context. Preserve the `coplay-unity-mcp` prefix.
4. Keep the master rule as routing and common operating principles. Do not move the full action catalog, this inventory or detailed handlers into its always-loaded body.
5. Check local links, MCP keyword arguments, CLI JSON, source provenance and master/index registration. Record runtime checks separately from static verification.
